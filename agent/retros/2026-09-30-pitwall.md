# Retro — pitwall (2026-09-30)

pitwall: batch ELT over Formula 1 data (OpenF1 → GCS → BigQuery → dbt → Observable site), released in lab v0.3.0–v0.4.0. Participants: Tomas and Claude. Format: me, Tomas, process.

## What went well
- Shipped end to end in five plans: extractor, lake, warehouse, dbt marts with data-quality rules, CI/CD with a scheduled production pipeline, and a live public site.
- Keyless by design: Workload Identity Federation for CI, read-only identity for the public site, no secret in the repo.
- Free tier held: two GCP projects, budget alerts, query quota, `make destroy` tested.

## What did not
- **Tutoring (Claude):** Tomas finished without understanding the dbt model logic, why some features existed, or parts of the code. End-of-block "Why" notes were not enough.
- **Assumptions (Claude):** org, billing currency, action tags and a dashboard tool's auth model were assumed, not verified — each cost rework.
- **Docs (process):** scattered across `docs/`, lab and project material mixed, no clear place for "how it works inside".
- **Self-improvement (Claude):** no proposal to improve my own system during the project.
- **Plans (process):** too long for what they carried.

## What Tomas asked for
Industry-standard technology over niche; tutoring at every step; simple, non-redundant, traceable docs that scale; agent docs separate from project docs (the repo as a world, projects as countries); excellence; cost and operations optimised — better, not more; visible improvement of Claude's memory and way of working each project; creativity; a private space for ideas.
